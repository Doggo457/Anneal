# Reading list

Ordered by when you need it. Tick things off and add a one-line note on what each one changed in your thinking.

## Week 1: the two methods the whole project rests on

- [ ] **LoRA: Low-Rank Adaptation of Large Language Models.** Hu et al., 2021. https://arxiv.org/abs/2106.09685
  Read sections 1 to 4 properly. The key idea is that the weight update during fine-tuning can be approximated by two small matrices, so you train a few million parameters instead of tens of billions.
- [ ] **QLoRA: Efficient Finetuning of Quantized LLMs.** Dettmers et al., 2023. https://arxiv.org/abs/2305.14314
  This is what makes a 32B model trainable on 64GB. Understand NF4 quantisation, double quantisation, and paged optimisers, at least at the "why does this save memory" level.

## Week 2: how people build coding models

- [ ] **Code Llama.** Rozière et al., 2023. https://arxiv.org/abs/2308.12950
- [ ] **Magicoder: Empowering Code Generation with OSS-Instruct.** Wei et al., 2023. https://arxiv.org/abs/2312.02120
  The dataset you'll probably start with comes from this paper. Read how they generated it and what they filtered.
- [ ] **StarCoder 2 and The Stack v2.** Lozhkov et al., 2024. https://arxiv.org/abs/2402.19173
  Skim. Useful for the licensing discussion of code training data.

## Week 3: how to measure it honestly

- [ ] **Evaluating Large Language Models Trained on Code** (the HumanEval paper). Chen et al., 2021. https://arxiv.org/abs/2107.03374
- [ ] **Program Synthesis with Large Language Models** (MBPP). Austin et al., 2021. https://arxiv.org/abs/2108.07732
- [ ] **Is Your Code Generated by ChatGPT Really Correct?** (EvalPlus, HumanEval+ and MBPP+). Liu et al., 2023. https://arxiv.org/abs/2305.01210
  Explains why the original benchmarks are too easy to game and why the "+" versions have many more tests.
- [ ] **LiveCodeBench.** Jain et al., 2024. https://arxiv.org/abs/2403.07974
  Contamination-resistant evaluation using problems published after a model's training cutoff. Relevant to the contamination worry in the brief.
