| 2026-09-19 | Base model and precision | I'm using Qwen/Qwen3.8-27B (dense, Apache-2.0, August 2026), trained with 8-bit LoRA by default and 4-bit QLoRA as the fallback. Baseline and fine-tune are evaluated at the same quantisation and thinking mode. It is in range, dense (so quantised training actually shrinks it), on Unsloth's supported path for the family, and among the strongest open 27B coders on the model card's numbers; 8-bit over 4-bit because Unsloth warns that 4-bit is lossy on this family. Published memory figures, to be measured on day one: the bf16 weights are 55.6 GB on disk; Unsloth's requirements table lists a 27B at 64 GB for 16-bit LoRA and 22 GB for 4-bit QLoRA as absolute minimums, and its Qwen3.8 page lists the 8-bit weights at 31 GB and bf16 at 56 GB. Usable memory is 48 GB on Windows or about 56 GB on Linux, so bf16 LoRA is over by 8 to 16 GB even on Linux, 8-bit lands around 37 to 41 GB and 4-bit around 22 GB (docs/Hardware-Notes.md). Withdrawn on the way: a 35B MoE with about 3B active parameters, considered first as the training target and then as an inference-only reference, can't be trained here because bitsandbytes leaves its fused expert tensors in bf16 (about 66 GB at any bit width), and as a reference it breaks the one-model agreement; a 9B dense model is below the agreed range. I'd revisit this if Qwen3.8-27B fails on ROCm in a way a version bump doesn't fix; docs/Model-Candidates.md lists same-shape and other dense fallbacks, and a switch restarts the baselines and is still one model. |
| 2026-09-19 | Context length | I'm running inference and every evaluation at the full 262,144-token context with a q8 KV cache (8 GB at full context; 16 GB in f16 would also fit), and training on 4,096-token examples (8,192 in 4-bit if memory allows), which doesn't change the model's context window. Full context is affordable because only 16 of the 64 layers are full attention, so the KV cache is 64 KB per token, and it makes repository-scale tasks possible in my personal evaluation set, which is what a local coding model is for. Long training examples are bounded by activation memory (my estimate then: about 54 GB for an 8k example even in 4-bit) and unnecessary, because LoRA doesn't alter positional handling. So my personal task set gains repository-scale tasks, the forgetting check gains a long-context probe so a short-example fine-tune can't silently dull long-context behaviour, and prompt-processing time at full context is measured on day one and budgeted for. I'd revisit this if the long-context probe drops after fine-tuning (then mix in longer examples) or prefill at full context is too slow for repository-scale evaluation (then cap the personal tasks at 64k to 128k). |
